# Rubrics 的实际用途和应用场景

**核心问题**: 生成的 rubrics 要拿去干什么？

---

## 一句话回答

**用 rubrics 自动给线上回复打分，识别 bad case（质量差的回复），并诊断差在哪里。**

---

## 完整应用流程

### Phase 3（已完成）：生成 Rubrics

```
输入: 452 道题目
处理: 多维度展开 → 准则实例化 → 归一化
输出: 452 个 rubrics（每个满分 100）

现在的状态: ✅ 有了"评分标准"
```

### Phase 4（待做）：用 Rubrics 判分

```
步骤 10: 生成回复池
  - 用多个模型生成回复（好的 + 差的）
  - 每道题 10-20 条回复
  
步骤 12: 判分
  - 用 rubric 给每条回复打分
  - 逐条检查：这条回复满足哪些准则？
  - 计算总分：sum(满足的准则分值) / 100
  
步骤 13: Bad Case 提取
  - 得分 < 60 的 → 标记为 bad case
  - 输出：未满足的准则清单
```

### 线上应用（最终目标）

```
用户提问
    ↓
模型生成回复
    ↓
用 rubric 自动打分 ───→ 得分 ≥ 60 → 通过 ✅
    ↓
    得分 < 60
    ↓
标记为 bad case ❌
    ↓
输出诊断报告：
  - 总分: 45/100
  - 未满足的准则:
    * 准则 3: 未说明合同负债结转路径 (-6.67分)
    * 准则 7: 未区分两者履约方向 (-6.67分)
    * ...
    ↓
人工复核/自动改进
```

## 实际案例演示

### 案例：会计学题目判分

**题目**: 合同负债和应付账款是什么意思？

**Rubric**（已生成）:
- 满分: 100
- 准则: 15 条（每条 6.67 分）

**回复 A**（高质量）:
```
合同负债是企业已收到客户款项但尚未履行交付义务的负债...
应付账款是企业已接受商品但尚未支付的负债...
合同负债后续结转为收入，应付账款通过支付货币资金冲销...
```

**判分过程**:
| 准则 | 满足？ | 得分 |
|------|--------|------|
| 准则 1: 说明合同负债定义 | ✅ | 6.67 |
| 准则 2: 说明应付账款定义 | ✅ | 6.67 |
| 准则 3: 区分两者义务性质 | ✅ | 6.67 |
| 准则 4: 说明结转路径 | ✅ | 6.67 |
| ... | ... | ... |
| **总分** | 满足 14/15 条 | **93.33/100** |

**判定**: 93.33 > 60 → **Good case** ✅

---

**回复 B**（低质量）:
```
合同负债就是欠款，应付账款也是欠款，都是负债。
```

**判分过程**:
| 准则 | 满足？ | 得分 |
|------|--------|------|
| 准则 1: 说明合同负债定义 | ❌ | 0 |
| 准则 2: 说明应付账款定义 | ❌ | 0 |
| 准则 3: 区分两者义务性质 | ❌ | 0 |
| 准则 6: 说明都是负债 | ✅ | 6.67 |
| 准则 7: 说明履约方式 | ❌ | 0 |
| ... | ... | ... |
| **总分** | 满足 1/15 条 | **6.67/100** |

**判定**: 6.67 < 60 → **Bad case** ❌

**诊断报告**:
```
Bad Case 分析:
- 总分: 6.67/100
- 主要问题:
  * 未说明合同负债的业务实质（收钱未履约）
  * 未说明应付账款的业务实质（收货未付款）
  * 未区分两者的结转路径
  * 未说明后续转化方向（收入 vs 成本）
- 改进建议:
  补充准则 1、2、3、11、12 的内容
```

## 为什么需要 Rubrics？

### 传统方式的问题

**人工评审**:
- ❌ 成本高（每条回复需要专家评审）
- ❌ 速度慢（无法处理大规模数据）
- ❌ 不一致（不同专家标准不同）
- ❌ 不可扩展（线上实时流量评不过来）

**简单打分**（1-5 分）:
- ❌ 颗粒度粗（只有总分，不知道差在哪里）
- ❌ 无法改进（不知道怎么改）
- ❌ 主观性强（5 分的标准是什么？）

### Rubrics 的优势

**自动化**:
- ✅ 成本低（一次生成，无限使用）
- ✅ 速度快（秒级判分）
- ✅ 一致性（同一 rubric 标准统一）
- ✅ 可扩展（处理百万级流量）

**细粒度**:
- ✅ 15-30 条准则（覆盖全面）
- ✅ 每条可判定（哪里好，哪里差）
- ✅ 可诊断（未满足的准则 = 问题清单）
- ✅ 可改进（按准则改进回复）

**客观可验证**:
- ✅ 二元判定（满足/不满足，无模糊地带）
- ✅ 可审计（为什么给这个分？看准则）
- ✅ 可验证（与人工标注对比一致性）

## 实际应用价值

### 1. 线上 Bad Case 挖掘（主要用途）

**场景**: 每天百万条对话，如何找出质量差的？

```python
# 线上流程
for query, response in daily_conversations:
    rubric = get_rubric(query)  # 匹配或生成 rubric
    score = judge(response, rubric)  # 用 rubric 打分
    
    if score < 60:
        badcase_queue.add({
            'query': query,
            'response': response,
            'score': score,
            'unmatched_criteria': [...]  # 诊断报告
        })
```

**价值**:
- 自动识别问题回复
- 按严重程度排序（分数越低越严重）
- 按失败维度聚合（事实正确性 vs 完整性）

### 2. 回复质量监控

**场景**: 模型升级后，质量有没有提升？

```
模型 A 平均得分: 72.3/100
模型 B 平均得分: 78.5/100
→ 模型 B 提升 6.2 分

按维度对比:
  事实正确性: A=85, B=88 (+3)
  完整性: A=68, B=78 (+10) ← 主要提升
  逻辑性: A=70, B=71 (+1)
```

### 3. 训练数据筛选

**场景**: 从大量数据中筛选高质量数据训练模型

```python
# 筛选高质量数据
high_quality = []
for query, response in dataset:
    score = judge(response, rubric)
    if score >= 85:  # 只要高分
        high_quality.append((query, response))

# 用高质量数据训练
model.train(high_quality)
```

### 4. 人工标注辅助

**场景**: 减少标注工作量

```
自动初筛:
  得分 > 80 → 自动通过（不需人工）
  得分 < 40 → 自动拒绝（不需人工）
  得分 40-80 → 人工复核

标注工作量减少 60-70%
```

### 5. 模型对齐

**场景**: 强化学习的奖励信号

```python
# RLHF 训练
reward = judge(response, rubric)  # rubric 作为奖励函数
model.update(reward)
```

## 类比理解

### Rubrics 就像...

**考试评分标准**:
- Rubric = 评分标准（15 条评分点）
- 回复 = 学生答卷
- 判分 = 按标准给答卷打分
- Bad case = 不及格的答卷

**代码审查 Checklist**:
- Rubric = 代码审查清单（命名、注释、性能...）
- 回复 = 提交的代码
- 判分 = 检查是否满足 checklist
- Bad case = 不符合规范的代码

**产品质检标准**:
- Rubric = 质检标准（尺寸、重量、外观...）
- 回复 = 出厂产品
- 判分 = 按标准检查产品
- Bad case = 不合格产品

## 总结

### 生成的 Rubrics 用来做什么？

1. **自动判分**（Phase 4）
   - 给回复打分（0-100）
   - 识别 bad case（< 60）

2. **质量诊断**
   - 哪些准则没满足
   - 差在哪里

3. **线上应用**（最终目标）
   - 实时监控回复质量
   - 自动挖掘 bad case
   - 辅助人工标注

4. **模型优化**
   - 筛选训练数据
   - 强化学习奖励
   - 质量对比评估

### 关键价值

- ✅ **自动化**：替代人工评审
- ✅ **细粒度**：不只是分数，还有诊断
- ✅ **可扩展**：处理大规模数据
- ✅ **一致性**：标准统一

### Phase 3 → Phase 4 → 线上

```
Phase 3 (已完成): 生成 452 个 rubrics（评分标准）
                         ↓
Phase 4 (待做): 判分验证（验证标准是否靠谱）
                         ↓
线上应用: 自动化 bad case 挖掘
```

---

**简单说**：Rubrics 是自动化的"质量评估工具"，让机器能像专家一样评判回复质量。
