# Rubric 生成建设：初定流程（B 版修订）

骨架取 Qworld RET（2603.23522），嫁接 RubricHub 三阶段（2601.08430），
诊断用 RIFT 八失效模式（2604.01375）。本文只定流程，数值见末节待定项。

---

## 前置：两件流程之外但必须先有的东西

**锚点集（人在环）**

- Qworld 的 Coverage / Uniqueness 都是**相对专家准则集**算的，我们没有专家集，必须自建一个小规模人工审定的 rubric 集当参照，否则第 11 步的指标没有分母
- 它同时是**独立于生成模型的质量参照点**。生成、诊断、回灌若共享同一信号源，准则会在自举中缓慢漂移而无人发现
- **不能进第 14 步的训练集**。一旦参与训练，它就不再独立，参照作用消失
- 审校重点放在自动诊断最弱的两类：Misaligned or Rigid（PWA 最低 80%）、Hackable

**模型角色分工（集群上要分开的）**

| 角色 | 用在哪步 | 硬约束 |
|---|---|---|
| 生成器 | 2–5、7、8 | 跑 RET，多轮调用，成本最高，后期蒸馏成小模型 |
| 聚合器 | 6 | 与候选生成模型可同源 |
| 判分器 | 12 | **必须与生成器不同源**，避免自偏好偏差 |
| 诊断器 | 11 | **异质组合**，按失效模式选型，不是挑一个最强的 |
| 回复池模型 | 10 | 多个异质模型 × 多档质量 |

不同前沿模型在 RIFT 各模式上强项互补：
Gemini 系在 Ungrounded（0.634 vs 0.444）、Subjective（0.909 vs 0.861）上强，
GPT 系在 Missing Criteria（0.686 vs 0.452）、Low Signal（0.667 vs 0.400）上强。

## 流程

### 1. 入口过滤

真人 query 甄别并进行缺陷判定（改写 / 弃用）。

- **真人甄别**：`eval_sample_prob = 0.1` 是强特征（机器构造的多为 0.8/0.9/0.95），叠加结构特征剔除 json_body 包裹、合成网格导航坐标、MCQ 模板、few-shot 分隔符。线上流大部分不是真人提问，这一步是必需前置，不是可选清洗
- **缺陷判定**取闭集：`直通` / `改写-截断补全` / `改写-指代消解` / `改写-拆分` / `弃用`
- **默认直通**。只有"使评分无法进行"才改。表达不优雅、口语化、缺礼貌用语都不改
- **最小改动**。改写会打破 query 与已有回复的对齐，一旦改到回复不再切题，判 `弃用` 而非强行改
- 自动检测器**只做召回不做判定**，逐条送 LLM 裁决。各检测器精度差异很大：多子题、填空题高；超短、首尾截断很低（首字截断规则约 10% 真阳，"是/的/在"开头的正常句子会大量误报）。宁漏不错

### 2. 上下文标签抽取

prompt-driven LLM 调用，从原始 query 中推断两个维度上下文标签。

- **intent**：提问的真实目的
- **隐性约束**：答案受众、格式、风险边界

`R⁰_h` —— 把根节点 Question Q 拆成 ℓ=1 层的 Scenarios。

- 两个标签是**下一步展开的输入**：Scenarios 从 intent + 隐性约束推出
- 每个 Scenario 带一个 `scenario_id`，供第 4 步挂血缘标签

### 2.5. 题型判定与路由

判定 query 属于哪种评价形态，路由到对应的 rubric 生成策略。

**判定依据**：
- 是否有唯一正确答案或可通过程序/公式验证
- 答案空间是离散有限（选择题、填空）还是连续开放
- 评价标准是客观可验证还是主观多维

**题型标签**：
- `verifiable`：数学题、代码正确性、事实性问答（"法国首都是哪里"）
- `open`：创作、建议、分析、解释（"如何提升团队士气"）
- `hybrid`：有确定性核心 + 开放性展开（"证明费马大定理并讨论其历史意义"）

**路由到 rubric_form**：
- verifiable → `gated_answer`（答案正确性为主，设闸门）
- open → `analytic`（多维度展开）
- hybrid → `multi_part`（分 block 处理）

| form | 适用 | 结构 | 是否跑完整 RET |
|---|---|---|---|
| `analytic` | open 题 | 多维度加权，R_w 全开，5–8 条准则 + 闸门 | **是** |
| `gated_answer` | verifiable 题 | 答案正确性占主导（≥ 60%）且设 major 闸门，推理过程与表达占余下 | **简化**：固定 3 个视角，不跑 R_w |
| `multi_part` | hybrid / 多子题 | 每子题一 block，块内归一，块间等权 | **分 block**：确定性 block 用 gated_answer，开放 block 用 analytic |

- 这一步是**新增的**，三篇骨架论文都没有。它们的定位都是"rubric 用于扩展到非可验证域"，verifiable 任务默认交给 RLVR。但我们要建统一能力，不能把数学题踢出去，所以在流程内部分流
- 判定本身是一次 LLM 调用，成本很低，但能避免大量无效的视角展开
- **不分流的代价**：数学题被强行套多视角展开，会产出「推理严谨度」「数学表达规范性」这类次要准则，而「答案对不对」这个主准则被稀释。RaR 的形式化说明了这一点——verifiable 任务本质上是 k=1、w=1 的单准则 rubric，硬拆成多维是错配

### 3. Perspective Elicitation

**若题型为 `analytic`，或 `multi_part` 的开放 block**，导出本题的评价轴 P_i，跑完整 RET。两个算子的分工：

**层次展开 R_h**：把每个 Scenarios（ℓ=1）往下拆。比如「面试 ML 工程师」这个场景 → 拆出「事实正确性」「推理质量」「数学严谨度」等视角。它是纵向分解，保证每条准则有场景归属。

**水平展开 R_w**：在每一层横向扫描，问「这个场景还漏了什么评价轴？」。比如上面拆出了事实、推理、数学，但漏了「是否给出工程可行建议」——R_w 会把它补进来。

**若题型为 `gated_answer`**，输出固定视角集，不跑 R_w：
- 答案正确性（主，占 60–80%，设 major 闸门）
- 推理过程完整性（次，占 15–30%）
- 表达清晰度（次要，占 5–10%）

- **R_w 在两层都要跑**（仅 analytic 路径）：ℓ=1 问"还漏了什么场景"，ℓ=2 问"还漏了什么评价轴"。只在 ℓ=2 跑会漏掉整个场景维度
- 每层的展开轮数是超参 `w_1` / `w_2`，轮数越多覆盖越全、成本越高
- 视角清单不预设固定集。Qworld 给的（事实正确性 / 完整性 / 推理质量 / 安全 / 风格 / 实用性）是示例而非枚举，长尾学科上要靠 R_w 现场导出
- **这一步是维度多样性的唯一来源**。种子集 2765 条准则维度去重只有一个值，病根就在没有这一层

### 4. 视角实例化为可测准则

每个视角实例化为可测准则。每条准则只能回答"是/否"，不能打模糊分。

**二元陈述**：准则本身就是一个可判定真伪的命题。比如「代码是否处理了空输入」——要么处理了，要么没有。不允许「代码清晰度 3/5 分」这种。

**重要性权重 α_c**：不是所有准则等权。同一道题里「答案事实正确」的权重远大于「是否提供了延伸阅读」。

**评分公式 s_c(A,Q) = α_c 或 0**：满足该条准则 → 得权重分 α_c；不满足 → 得 0。不存在「部分满足得 0.6α_c」。

- 二值制是刻意的，对应 RIFT 的 **Non-Atomic**：捆绑式或分档式准则会导致判分器给分不一致
- **每条准则必须携带血缘标签**（`scenario_id` + `perspective` + `rubric_form`）。第 13 步按视角聚合、第 14 步反馈到第 3 步，全靠这个标签，后补补不上
- α_c 由生成器给初值，第 6 步聚合时校准，第 11 步诊断后可调
- 准则措辞要尽量 **constitutive 而非 presupposing**：写「回复是否说明水结冰膨胀源于氢键」（判分器只需核对是否出现），而不是「回复对水结冰膨胀的解释是否科学准确」（把判断难题整个甩给判分器）

### 5. Response Grounding

将之前产出的候选准则集作为初稿，取强模型参考回答 o_i 作为锚定。

**meta-principles 约束**：同时在 prompt 里注入几条上层原则约束生成方向（如「准则必须对应回复中可观察到的行为」「准则不得要求回答超出题目范围的额外内容」）。

对照 meta-principles 检查准则，判断准则是否 drift，治 rubric drift。

- **锚定用的回复必须与待评回复不同源**。种子集阶段用 glm52 / gpt55 作锚是成立的（它们不是被评对象）；但真实流上，日志里那条回复**就是待评对象**，拿它锚定会让 rubric 从待评回复自身衍生出来——它漏掉的内容不会成为准则，覆盖率虚高、badcase 漏检
- 所以真实流上二选一：用强模型现生成一条参考回复作锚，或跳过锚定只留 meta-principles 检查。**不能拿日志回复当锚**
- drift 的表现是准则变笼统、幻觉、脱离实际输出。判定后不合格的退回第 3 步重新展开，不是原地改措辞
- `gated_answer` 题的锚定重点不同：锚的是**标准答案本身**，而非回复的表达方式

### 6. Multi-Model Aggregation

让各个优质模型独立生成候选准则，然后取并集，聚合 prompt 去冗余、解冲突、补标签。

输出一个去重消噪后的基础准则集 R_base，维度覆盖面比单模型显著更广。

- **每个模型独立跑完第 2–5 步**，不是只重跑第 4 步。perspective bias 产生在展开阶段，只重跑实例化补不了盲区
- 模型必须**异质**（不同厂商 / 不同系列）。同系列模型共享盲区，取并集等于白跑
- **补标签**指补齐第 4 步的血缘标签（`scenario_id` + `perspective` + `rubric_form`）和权重 α_c。聚合时准则会被合并改写，标签要跟着传递，不能丢
- 解冲突指两个模型对同一要求给出方向相反或严格程度不同的准则，聚合时择一或合并
- 种子集维度退化成一个值，最可能的成因就是单模型的 perspective bias。这一步和第 3 步的 R_w 是互补的：一个从数据源补，一个从算法结构补
- **`verifiable` 题的聚合另有一用**：多个模型对同一道数学题的答案若不一致，说明这题本身有歧义或超出模型能力，应标记待人工复核而非强行生成 rubric

### 7. Difficulty Evolution

取一对高分回复，对照两者，抽取增量准则，使得合格回复和高阶回复有分数梯度。

- **高分对怎么选**：用第 6 步的 R_base 先给候选回复打分，取共识高分的前两条。这一步依赖第 6 步的产出，不能提前
- 增量准则的形态是**把泛准则升级为严准则**：「代码正确吗」→「是否以 O(n) 复杂度处理边界情形」
- 治的是 score saturation：基础准则只能判对错，分不出优秀与卓越，顶部模型全部撞满分就没有优化梯度
- 我们只有固定的两条强模型回复，多样性有限。若抽不出有意义的增量准则，需要在集群上补生成候选回复（与第 10 步共用产能）
- R_final = R_base ∪ R_add
- **`gated_answer` 题可跳过本步**。数学题的"优秀 vs 卓越"差异很小——答案要么对要么错，过程完整性层次也不多。若要做，只在推理过程维度上做轻量演化（如「是否说明了每步的依据」）

### 8. 惩罚项

惩罚项与正向准则进行互补，有严重度分级（RubricHub Appendix D.2 给了独立模板，可以直接照搬）。

- 惩罚项是**独立生成环节**，不是正向准则取反的副产品
- **必须 instance-specific**，枚举本题的具体错误模式。写「是否出现事实性错误」这种模板句就是 RIFT 的 **Ungrounded**（没给核验依据和边界）。种子集 98% 的负向项是同构模板，这是相对现状最容易做出可见提升的一处
- 严重度分级对应不同机制，不是不同分值：
  - 安全类违规 → 总分置 0
  - 核心结论性事实错误 → 总分截断至上限（上限值待定）
  - 次要瑕疵 → 不设闸门，走对应正向准则不得分即可
- 分级机制是"闸门"而非"扣分"：核心概念答错本质是回复不合格，线性扣分会让「大段正确内容 + 一处核心错误」仍拿高分，这是可被钻空子的口子
- RaR 用的分类标签可参考：Essential / Important / Optional / **Pitfall**，惩罚项对应 Pitfall 一类，权重给到 0.9（接近 Essential 的 1.0）

### 9. 归一

S(A,Q) = F_norm(Σ s_c) = Σ s_c / S_max

- S_max = Σ α_c（仅正向准则）。**闸门项不进分母**，它作用于总分而非贡献分值
- 归一后每题满分恒定，跨题可比。这是第 13 步 badcase 阈值能全局设一个的前提——不归一则阈值只能逐题手调
- 第 10 步跑完可用实际分数区间反过来校准 F_norm
- **三种 form 归一后同量纲**，这样 verifiable 题和 open 题的 badcase 可以放在同一个阈值下比较

### 10. 回复池

用 rubric 先去评一堆真实的、质量不等的回复，看分数分布。

**多模型 × 多档质量生成回复**：在集群上跑多个异质模型，对同一道题各出几条回复，故意拉开质量梯度——有强回复、有弱回复、有中间档回复。不是随便跑，是按质量档位规划过的。

两个用途：

- **Consequential 类诊断的输入**：Hackable 看弱回复是否能钻空子拿高分，Low Signal 看不同质量的回复分数是否拉得开。都需要这批回复做载体。
- **S5 归一分母校准**：S_max 是理论满分，但实际情况可以拿这批回复跑一遍看实际分数区间，校准归一函数。

- **弱档怎么造**：三种方式并存——截断至部分长度、删掉一个关键论点、换小模型生成。三种造出的"弱"不是同一种弱，只用一种会让 Low Signal 的结论随造法漂移
- 若同一准则在三种造法下结论不一致，说明它测的是长度或结构而非内容，本身就是 Hackable 的信号
- 强档可直接复用现有强模型回复，不必重跑
- **`verifiable` 题的弱档要另造**：截断和删论点对数学题意义不大，应该造"答案错但过程看似完整"的回复——这才是 gated_answer 形态真正要防的钻空子方式

### 11. 全量诊断

RIFT 八种失效模式。

| 类别 | 失效模式 | 定义 | 诊断方式 | 需回复池 |
|---|---|---|---|---|
| Reliability | Subjective | 用主观词（"清晰"、"适当"）且未用客观期望锚定 | LLMaJ-MV（N=5 多数票），Gemini 系为主 | 否 |
| | Non-Atomic | 结构不可解析、不可一致评分，或捆绑多条导致无法给部分分 | LLMaJ-MV（N=5 多数票） | 否 |
| | Ungrounded | 准则需对照事实核验，但没提供依据、边界或核验程序 | LLMaJ-MV，Gemini 系为主（F1 0.634 vs 0.444） | 否 |
| Content Validity | Misaligned or Rigid | 评错了目标、嵌入错误假设，或提出题目没要求的过严限制 | 异质模型组合 → 人工（PWA 最低，80%） | 否 |
| | Missing Criteria | 题目隐含了可核验的要求，但 rubric 没有对应准则 | GPT 系为主（F1 0.686 vs 0.452） | 否 |
| Consequential | Hackable | rubric 层面可被钻空子：靠虚增代理指标就能拿满分 | Reward variance / IRR，可叠 LLMaJ-MV | 是 |
| | Low Signal | 整体区分不开候选回复，对质量差异明显的回复给出近乎相同的分 | 单次跑或 Reward variance（多数票会变差） | 是 |
| | Redundant Criteria | 两条以上准则评的是同一个底层要求，同一行为被重复计分 | LLMaJ-MV 反而变差，该用单次跑 | 否 |

**诊断出问题后的处置**（诊断没有处置就只是报告）：

- Subjective / Ungrounded / Non-Atomic → 重写该条准则的措辞或拆分，重写后仍不过则删
- Redundant Criteria → 合并同簇准则，权重按簇内均分而非各自累加
- Missing Criteria → 退回第 3 步，对应视角补水平展开
- Misaligned or Rigid → 退回第 2 步，上下文标签抽错了；**若发现是题型判错**（把数学题当开放题展开），退回第 2.5 步
- Hackable → 该条准则降权或改为闸门
- Low Signal → 整份 rubric 层面的问题，退回第 7 步补增量准则

**按 form 分别看诊断结果**：`gated_answer` 题若频繁触发 Low Signal，多半是题型判定过宽（把开放题误判为确定性题）；`analytic` 题若频繁触发 Misaligned or Rigid，多半是判定过窄。这两个信号是校准第 2.5 步的主要依据。

**执行顺序按成本排**：不需回复池的五项先跑（最便宜），需回复池的两项后跑，人工那项最后跑——前面几轮会删掉一批准则，对已删准则做人工标注是浪费。

**诊断通过后冻结**：rubric 定稿即锁定，并记录绑定的判分器版本。同一份 rubric 在不同模型上会碎片化，换判分器后 Reliability 三项要重跑。

### 12. 判分

逐条判定第 4 步的二元判定，输出 y/n + 引用回复原文中的证据句，输出 y 得到 α_c，n 得 0。加总交给归一判断。

- **判分器必须与生成器不同源**，否则自偏好偏差会让判分虚高
- 强制引用证据句有两个作用：抑制判分漂移，以及白送一条审计链。代价是 token 上升，评估线全开、训练线按比例抽样
- 判分时准则顺序、回复位置都会引入偏差，同一批判分要固定呈现顺序
- **`gated_answer` 题的答案正确性项可以走程序化核验**（数学答案精确匹配、代码跑测试用例），不必过 LLM。这是 RLVR 的做法，在这一档里直接复用，比 LLM 判分更可靠且更便宜

### 13. Badcase 提取

低分就是 badcase。未达准则清单即失败原因，按照视角聚合。

- 阈值待定，但因为第 9 步已归一，可以全局设一个而不必逐题调
- 输出形态是「分数 + 未达准则列表 + 每条的证据句」，直接可读，不需要人工归因
- 按第 4 步的 `perspective` 标签聚合，天然得到失败模式分布（事实正确性 / 完整性 / 推理质量 / 安全 / 实用性 各占多少），不需要另做聚类
- 这是相对标量打分的主要增量：不只说"这条差"，还直接给出差在哪一条准则
- **按 `rubric_form` 二次聚合**：verifiable 题的 badcase 是"知识/计算错误"，open 题的 badcase 是"维度缺失或质量不足"。两类的改进动作完全不同，混在一起看会失焦

### 14. 回灌

将全通过的 rubric 视为高质量产出，把 query、rubric 丢进训练集。

将某个频繁出问题的视角反馈给第 3 步，说明该视角拆分有问题，需要调整。

- **锚点集不进训练集**。它是独立参照点，一旦参与训练，自指涉循环重新闭合
- 自举边界：Reliability 三项全自动，可以无限自举；Content / Consequential 类依赖人工，**每轮迭代必须同步扩充锚点集**，否则准则方向会缓慢漂移而无人发现
- 反馈到第 3 步的粒度是**视角**而非单条准则：某视角下的准则频繁触发 Missing 或 Misaligned，说明该视角的拆分方式有问题，改 R_h 的拆法而不是逐条打补丁
- 若某视角频繁触发 Hackable，则是该视角本身容易被表面特征满足，考虑降权或改闸门
- **题型判定的误判率也要回灌到第 2.5 步**：统计被诊断打回并改判 form 的比例，若持续偏高说明判定规则需要修

## 待定项

**结构类**（跑通后定）

- R_w 的展开轮数 w_1 / w_2
- 视角清单的稳定条目（Qworld 给的是示例，长尾学科靠现场导出）
- `gated_answer` 里答案正确性的占分比例（暂定 60–80%）
- 惩罚项严重度分级的上限值
- 准则条数的上下界（RaR 用 7–20 条，Qworld 无固定值）

**阈值类**（有回复池后定）

- RIFT 八项各自的判定阈值（论文的 F1 是在其模型档位上取的最优阈值，换我们集群的模型后要重测，数字不可直接搬）
- badcase 分数阈值
- LLMaJ-MV 的 N（论文用 5）
- 题型判定的置信度阈值——低置信度的 query 该走哪条路径

**规模类**

- 锚点集题数（太小则 Coverage / Uniqueness 噪声大，太大则人工成本失控）
- 回复池每档条数、三种弱档造法的配比
- 第 6 步用几个异质模型
- 三种 form 在数据里的实际占比（决定各路径的产能分配）
