## 真正的问题在哪里？

### ❌ 不是论文设计的问题

完整流程（s04→s09）**已正确实现**，我检查了代码：
- ✅ `stages/s04_criteria.py` - 视角实例化为准则
- ✅ `stages/s05_grounding.py` - Response Grounding，防止 drift
- ✅ `stages/s06_aggregate.py` - 多模型聚合
- ✅ `stages/s07_difficulty.py` - Difficulty Evolution
- ✅ `stages/s08_penalties.py` - 惩罚项独立生成
- ✅ `stages/s09_normalize.py` - 归一化

### ❌ 也不是完整流程的逻辑错误

查看 `s06_aggregate.py` 的聚合策略：

```python
SIM_THRESHOLD = 0.75  # Jaccard 相似度阈值，太高了！

# 问题: 只合并几乎一模一样的准则
# 例如下面这两条，Jaccard < 0.75，所以没合并：
#   "明确指出合同负债产生于已收客户对价但尚未转让商品"
#   "明确指出应付账款产生于企业已接受商品但尚未支付款项"
```

### ✅ 真正的问题：聚合去冗余不够强

论文设计的逻辑是：
1. 充分生成（多视角、多模型、增量） - **宁可多生成**
2. 聚合去冗余（合并重复、按权重截断） - **在这里控制数量**

但当前 `s06_aggregate.py` 的去冗余**太弱**：
- 阈值太高（0.75）- 只合并几乎一模一样的
- 只做字面匹配（Jaccard）- 语义相似但表述不同的合并不了
- 聚合后没有截断 - 保留了所有准则

## 正确的修复方向

### ❌ 错误方向（s04L 的做法）

```
跳过 s05/s06/s07/s08，在生成时硬约束 6-8 条
  ↓
失去质量保证机制（锚定、多模型、演化、惩罚项）
  ↓
准则质量下降（空泛、编造、脱靶）
```

### ✅ 正确方向（改进完整流程）

```
保留 s04→s05→s06→s07→s08→s09 完整流程
  ↓
改进 s06 聚合策略：
  1. 用语义相似度（embedding）替代 Jaccard
  2. 降低阈值到 0.6-0.65（更激进合并）
  3. 聚合后按权重排序，截断到前 8-10 条
  ↓
既保证质量，又控制数量
```
