# S04L 与论文原始设计的对比分析

**分析日期**: 2026-08-12  
**分析者**: Claude Opus 5  
**对比对象**: 
- 当前实现: `stages/s04L_rubric.py`
- 论文设计: `docs/design/rubric_pipeline_full_v2.md` 中的 RubricHub 三阶段

---

## 核心问题发现

### ❌ 严重偏离：s04L 跳过了 RubricHub 的关键步骤

| RubricHub 原始设计 | s04L 实现 | 偏离程度 |
|-------------------|----------|---------|
| **Step 4**: 视角实例化为准则（每视角 1-3 条） | ✅ 保留（但方式不同） | 中等 |
| **Step 5**: Response Grounding（锚定强模型回复） | ❌ **完全跳过** | **严重** |
| **Step 6**: Multi-Model Aggregation（多模型候选→聚合） | ❌ **完全跳过** | **严重** |
| **Step 7**: Difficulty Evolution（高分对抽增量准则） | ❌ **完全跳过** | **严重** |
| **Step 8**: 惩罚项（独立生成，instance-specific） | ⚠️ 部分实现（1-2条通用） | 中等 |

---

## 详细对比

### 1. Step 5: Response Grounding - **完全缺失**

#### 论文原始设计
```
将之前产出的候选准则集作为初稿，取强模型参考回答 o_i 作为锚定。

meta-principles 约束：同时在 prompt 里注入几条上层原则约束生成方向
（如「准则必须对应回复中可观察到的行为」「准则不得要求回答超出题目范围的额外内容」）。

对照 meta-principles 检查准则，判断准则是否 drift，治 rubric drift。
```

**关键机制**:
- 用强模型生成的**参考回复**作为锚点
- 检查准则是否能在参考回复中找到对应的可观察行为
- 防止准则 drift（变笼统、幻觉、脱离实际输出）

#### s04L 实现
```python
# 完全没有这个步骤
# 直接从视角跳到生成准则，无锚定机制
```

**后果**:
- ✗ 准则可能要求回复中不可能出现的内容
- ✗ 准则可能过于抽象，判分器无法核验
- ✗ 没有对照真实回复的反馈回路

---

### 2. Step 6: Multi-Model Aggregation - **完全缺失**

#### 论文原始设计
```
让各个优质模型独立生成候选准则，然后取并集，聚合 prompt 去冗余、解冲突、补标签。

输出一个去重消噪后的基础准则集 R_base，维度覆盖面比单模型显著更广。

- 每个模型独立跑完第 2–5 步，不是只重跑第 4 步
- 模型必须异质（不同厂商 / 不同系列）
- 补标签指补齐血缘标签和权重 α_c
```

**关键机制**:
- **多个异质模型**各自独立生成准则
- 取**并集**，覆盖不同模型的视角盲区
- 聚合时去冗余、解冲突、补标签

#### s04L 实现
```python
# 只用一个模型（RP_M_GEN）一次生成
m = stage.pick('RP_M_GEN', 'generator')
obj, _ = stage.json_call(m, build(r), stage='s04L', thinking=THINK)
```

**后果**:
- ✗ **单模型的 perspective bias**：视角盲区无法补齐
- ✗ 维度覆盖不全（这就是为什么种子集维度去重只有1个值）
- ✗ 缺少多模型共识机制

**论文明确指出**:
> 种子集维度退化成一个值，最可能的成因就是**单模型的 perspective bias**。
> 这一步和第 3 步的 R_w 是互补的：一个从数据源补，一个从算法结构补。

---

### 3. Step 7: Difficulty Evolution - **完全缺失**

#### 论文原始设计
```
取一对高分回复，对照两者，抽取增量准则，使得合格回复和高阶回复有分数梯度。

增量准则的形态是把泛准则升级为严准则：
「代码正确吗」→「是否以 O(n) 复杂度处理边界情形」

治的是 score saturation：基础准则只能判对错，分不出优秀与卓越。
```

**关键机制**:
- 对比**高分回复对**，找出差异点
- 生成**增量准则**（更高标准）
- 避免顶部模型全部撞满分

#### s04L 实现
```python
# 完全没有这个步骤
# 所有准则都是基础级别，无分层
```

**后果**:
- ✗ 准则粒度单一，只能判"对/错"，不能判"好/优秀"
- ✗ 高水平回复和中等回复可能拿到相同分数
- ✗ 缺少优化梯度

---

### 4. Step 8: 惩罚项 - **严重简化**

#### 论文原始设计
```
惩罚项是独立生成环节，不是正向准则取反的副产品。

必须 instance-specific，枚举本题的具体错误模式。
写「是否出现事实性错误」这种模板句就是 RIFT 的 Ungrounded。

种子集 98% 的负向项是同构模板，这是相对现状最容易做出可见提升的一处。

严重度分级对应不同机制：
- 安全类违规 → 总分置 0
- 核心结论性事实错误 → 总分截断至上限
- 次要瑕疵 → 不设闸门，走对应正向准则不得分即可
```

**关键原则**:
- **独立生成**（不是正向准则的反面）
- **instance-specific**（本题的具体错误，不是模板）
- **严重度分级**（闸门机制，不是简单扣分）

#### s04L 实现
```python
【扣分项】1-2 条，只写**真正致命**的错误（结论答反、核心概念用错）。
直接写错误现象本身，is_positive 填 false。

⚠️ **扣分项禁止编造具体细节**：
- 如果题目有参考错误回复，可基于真实错误写具体准则
- 如果没有参考错误，只写**通用错误类型**...
```

**后果**:
- ⚠️ 数量限制（1-2条）vs 论文要求（独立环节，可多条）
- ⚠️ 鼓励"通用错误类型" vs 论文要求（instance-specific）
- ✗ 没有严重度分级机制（闸门）
- ✗ 没有基于参考错误回复生成

**这是当前问题的根源之一**：我们的修复（"禁止编造具体细节"→"写通用类型"）实际上**违背了论文设计**！论文明确说"通用模板"是 Ungrounded 失效模式。

## 根本问题诊断

### 问题1: s04L 的"预算制"设计与论文冲突

#### s04L 的设计思想
```python
"""
原流程的膨胀链（实测）：
    3.2 场景 → 17.8 视角 → 25.3 准则 → 30.5 最终

这一步用「全题预算制」取代「逐视角展开」：
把视角当作**覆盖提示**而非展开单元，
让模型在 6-8 条的总预算内自己决定哪些视角值得成为准则。
```

#### 论文的设计思想
```
步骤4: 每个视角实例化为可测准则（1-3条/视角）
步骤5: Response Grounding（锚定调整）
步骤6: Multi-Model Aggregation（取并集，去冗余）
步骤7: Difficulty Evolution（增量准则）
步骤8: 惩罚项（独立生成）
步骤9: 归一化

最终数量控制在聚合和去冗余时做，不是在生成时硬约束。
```

**核心矛盾**:
- s04L: 用"6-8条预算"强制模型做取舍 → **在生成时压缩**
- 论文: 先充分生成（多视角、多模型、增量），后聚合去冗余 → **在聚合时压缩**

论文的逻辑是：**宁可多生成后去重，也不要生成时遗漏**。
s04L 的逻辑是：**在生成时就控制数量，避免后续去重的成本**。

**论文的证据**:
> 这一步是**维度多样性的唯一来源**。种子集 2765 条准则维度去重只有一个值，
> 病根就在没有这一层。（指 Step 3 + Step 6 的多模型聚合）

---

### 问题2: 缺少"锚定机制"导致准则脱靶

#### 论文的警告
```
drift 的表现是准则变笼统、幻觉、脱离实际输出。
判定后不合格的退回第 3 步重新展开，不是原地改措辞。
```

#### s04L 的表现
- ✗ 准则空泛（"结论表述清晰"）
- ✗ 准则编造细节（"将52错误解码为S"）
- ✗ 准则超出范围（题目没问的要求）

**这些正是 drift 的症状！**

---

### 问题3: prompt 中的"禁止"约束治标不治本

#### 当前 s04L 的做法
```python
【三条禁止】
1. 禁止写不确定的机理断言
2. 禁止超出题目范围
3. 禁止空泛词
...
【扣分项禁止编造具体细节】
```

#### 论文的做法
```
不是靠 prompt 禁止，而是靠流程机制：

1. Response Grounding: 用真实回复锚定，准则必须能在回复中找到对应
2. Multi-Model Aggregation: 多模型共识，异常准则会在聚合时被识别
3. RIFT 诊断: 自动检测 Ungrounded / Subjective / Non-Atomic
4. 处置动作: 删除 defective 准则
```

**对比**:
- s04L: 用 prompt 约束 → **依赖 LLM 遵守**，不可靠
- 论文: 用流程机制 → **系统性保证**，可验证

```python
def grounding(r, candidate_rubrics):
    """用强模型参考回复锚定准则。"""
    # 生成参考回复（如果没有）
    if not r.get('anchor_response'):
        anchor = generate_reference_response(r['question'])
    else:
        anchor = r['anchor_response']
    
    # 检查每条准则是否能在参考回复中找到对应
    grounded_rubrics = []
    for c in candidate_rubrics:
        prompt = f"""
        参考回复: {anchor}
        准则: {c['criteria']}
        
        这条准则是否能在参考回复中找到对应的可观察行为？
        如果准则要求的内容在参考回复中无法验证，标记为 drift。
        """
        result = llm_check(prompt)
        if not result['is_drift']:
            grounded_rubrics.append(c)
    
    return grounded_rubrics
```

#### 2. 实现 Multi-Model Aggregation (Step 6)

```python
def multi_model_aggregation(r, models):
    """多模型生成 → 聚合去冗余。"""
    all_candidates = []
    
    # 每个模型独立生成
    for model in models:
        candidates = generate_rubrics_single_model(r, model)
        all_candidates.extend(candidates)
    
    # 聚合: 去冗余、解冲突、补标签
    aggregated = aggregate_candidates(all_candidates)
    
    return aggregated

def aggregate_candidates(candidates):
    """聚合多模型的候选准则。"""
    prompt = f"""
    以下是多个模型生成的候选准则，请：
    1. 去除语义重复的准则（保留表述最清晰的）
    2. 解决冲突的准则（选择更合理的，或合并）
    3. 确保每条准则都有 dimension 和 perspective_ids
    
    候选准则:
    {json.dumps(candidates, ensure_ascii=False, indent=2)}
    """
    return llm_aggregate(prompt)
```

## 根本原因总结

### 1. 设计哲学偏离

| 维度 | 论文设计 | s04L 实现 |
|------|---------|----------|
| 数量控制 | 聚合时压缩（先多后少） | 生成时压缩（直接少） |
| 质量保证 | 流程机制（锚定、聚合、诊断） | prompt 约束（禁止词） |
| 多样性来源 | 多模型 + R_w | 单模型 + 视角提示 |
| 惩罚项策略 | instance-specific | 通用模板（或编造） |

### 2. 缺失的关键机制

1. **Response Grounding**: 无锚定 → 准则脱靶、空泛、幻觉
2. **Multi-Model Aggregation**: 单模型 → 视角盲区、维度单一
3. **Difficulty Evolution**: 无分层 → 准则粒度单一
4. **instance-specific 惩罚项**: 通用模板 → RIFT Ungrounded

### 3. 为什么跑出来的 rubrics 有问题

| 问题表现 | 论文预测 | s04L 缺失机制 |
|---------|---------|--------------|
| 维度单一（1个值） | perspective bias | Multi-Model Aggregation |
| 准则空泛 | rubric drift | Response Grounding |
| 准则编造细节 | Ungrounded | Response Grounding + 错误的惩罚项策略 |
| 准则非原子 | Non-Atomic | RIFT 诊断后未处置 |
| 答案项占比偏离 | 缺少严格的形态约束 | gated_answer 路径未充分简化 |

## 真正的问题所在

### 问题不是"流程设计错了"，而是"去冗余不够"

查看 `stages/s06_aggregate.py` 的聚合策略：

```python
SIM_THRESHOLD = 0.75  # Jaccard 相似度阈值

def jaccard(s1, s2):
    """计算两个字符串的 Jaccard 相似度"""
    set1, set2 = norm(s1), norm(s2)
    if not set1 or not set2:
        return 0.0
    return len(set1 & set2) / len(set1 | set2)
```

**问题**:
- 阈值 0.75 太高（只合并几乎一模一样的准则）
- 上面 q0002 的 19 条准则，很多语义重复但字面不同，Jaccard < 0.75 所以没合并

**论文的本意**:
- 聚合应该**更激进地去冗余**
- 而不是简单的字面匹配

## 具体修复建议（v3）

### 方案A：改进聚合（推荐）

**修改 `stages/s06_aggregate.py`**:

```python
# 1. 用语义相似度替代 Jaccard
from sentence_transformers import SentenceTransformer
model = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')

def semantic_similarity(s1, s2):
    """计算语义相似度"""
    emb1 = model.encode(s1)
    emb2 = model.encode(s2)
    return cosine_similarity([emb1], [emb2])[0][0]

# 2. 降低阈值，更激进合并
SIM_THRESHOLD = 0.65  # 从 0.75 降到 0.65

# 3. 聚合后按权重排序，强制截断
def post_aggregate_filter(criteria, max_count=10):
    """聚合后的后处理：按权重排序，保留前N条"""
    # 按 score 排序
    sorted_criteria = sorted(criteria, key=lambda c: -c.get('score', 0))
    # 保留前 max_count 条
    return sorted_criteria[:max_count]
```

**预期效果**:
- 30.5 条 → 8-10 条（通过语义去冗余）
- 保留完整流程的质量保证机制
- 避免 s04L 的质量问题
