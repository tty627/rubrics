## 发现的问题类型

### 1. ❌ 严重：负向准则编造具体数值 (23题)

**表现**：负向准则中包含编造的具体数值/字节/参数，而非基于参考错误。

**典型案例**：
- `q0303`: "将十六进制序列'52'错误解码为字符'S'以外的其他字符"  
  → 52应解码为'R'，这里把52和53混淆了，且无参考依据
- `q0383`: "将软化温度错误地等同于熔融温度（170-180°C）"  
  → 编造了具体错误数值
- `q0096`: "将CaCl2的摩尔质量错用为40+35.5=75.5"  
  → 编造了具体错误计算

**根本原因**：
- s04L prompt 要求 LLM "想象致命错误"，但未给参考错误案例
- 对于只有1条参考回复的记录（64题），LLM 被迫编造具体错误
- 缺少"禁止编造具体细节"的明确约束

**影响**：
- 负向准则失去可判定性（判分器如何知道是否"52解码错"？）
- 引入虚假诊断信号（该错误可能从未真实发生）

**流程定位**：`stages/s04L_rubric.py:61-62`，prompt 设计缺陷

---

### 2. ❌ 严重：verifiable 题答案项占比偏离 (21题)

**表现**：
- **<60%**：18题，最低21% (q0127)、25% (q0049)、30% (q0079)
- **>80%**：3题，最高89% (q0348)

**设计目标**：答案项应占 60-80%（s04L_rubric.py:86-87）

**典型案例** (q0079):
```
满分10分，答案项仅3分(30%)
  +3 第一空答案正确：F(M)的最大值为 40
  +3 第二空答案正确：M 的值为 8448  ← 应该是这条，但被打散了
  +1 推理步骤1
  +1 推理步骤2
  +1 推理步骤3
  +1 指令遵循
```

**根本原因**：
- LLM 把"答案正确性"拆成了多条推理步骤准则（各1分）
- prompt 中"答案正确性那条给 6-8 分"的约束**未被有效执行**
- 可能是 prompt 中"推理步骤"类视角误导 LLM 分散了分值

**流程定位**：`stages/s04L_rubric.py:66-69`，分值分配指导不够强

---

### 3. ⚠️  中等：准则表述空泛 (28题)

**表现**：准则文本过短（<20字）且含空泛词（准确/完整/清晰等）。

**典型案例**：
- `q0026`: "结论表述清晰，无歧义或模棱两可"
- `q0008`: "完整列出全部六十四卦，无遗漏或重复"
- `q0090`: "正确求出二次函数在 R 上的最大值"

**根本原因**：
- prompt 禁止了"回答准确"，但未禁止"结论准确"、"答案准确"
- LLM 绕过了禁止词，用同义变体表达空泛要求

**流程定位**：`stages/s04L_rubric.py:51-52`，禁止词列表不完整

---

### 4. 其他问题

- **满分>15** (1题 q0452): 粒度过细，18分拆成过多准则
- **答案项占比>80%** (3题): 其他准则权重过低，不合理

## 修复方案

### 短期（立即修复）

1. **改进 s04L prompt**（已完成）：
   - ✅ 添加"禁止编造具体数值"约束
   - ✅ 传递 ref_errors 信息，区分有无参考错误
   
2. **强化答案项占比约束**：
   - 在 parse() 中检查 gated_answer 的答案项占比
   - 若不在 60-80%，自动调整分值（提高答案项，压缩其他项）

3. **扩展禁止词**：
   - "准确"、"完整"、"清晰"、"正确" 必须与具体内容绑定
   - 示例：❌"结论准确" → ✅"结论明确指出合同负债属于负债类科目"

### 中期（补齐诊断）

4. **为 s04L 接入 RIFT 诊断**：
   - 方案A：修改 s11_diagnose.py，支持读取 s04L_rubric.jsonl
   - 方案B：写 s11L_diagnose.py，专门诊断 lean 流程
   
5. **导出时过滤 defective 准则**：
   - `export_advisor_schema.py` 增加 `--diagnosed` 参数
   - 读取 s11L_diagnosed.jsonl，跳过 verdict=defective 的准则

### 长期（改进机制）

6. **自动化占比校验**：
   - s04L parse() 中添加后处理：检查 gated_answer 占比，不达标则调整
   
7. **参考错误回复的采集**：
   - 当前 ref_errors 只有标签，缺少错误回复文本
   - 补充 ref_error_responses 字段，供 s04L 生成负向准则时参考
