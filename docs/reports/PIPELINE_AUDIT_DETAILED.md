## 🔴 严重偏差（阻碍线上应用）

### 1. **步骤 9 归一化未完成** ⚠️ **最严重**

**设计要求** (docs §9, 行 169-176):
```
S(A,Q) = F_norm(Σ s_c) = Σ s_c / S_max

- S_max = Σ α_c（仅正向准则）
- **归一后每题满分恒定，跨题可比**
- 这是第 13 步 badcase 阈值能全局设一个的前提
  ——不归一则阈值只能逐题手调
- **三种 form 归一后同量纲**
```

**实际实现** (`stages/s09_normalize.py`, 行 32-43):
```python
# 算 S_max（只算 base + dist）
s_max = sum(c['score'] for c in r['criteria']
            if c.get('criterion_type') in ('base', 'dist'))

# 归一化所有准则
for c in r['criteria']:
    if c.get('criterion_type') == 'penalty':
        c['normalized_score'] = -(abs(c['score']) / s_max) * 100
    else:
        c['normalized_score'] = (c['score'] / s_max) * 100
```

**偏差**:
- ❌ **s_max 保存为绝对值 (18-374)**，未归一化到 0-100
- ❌ **normalized_score 已乘以 100**，但这只是准则内部的归一化
- ❌ **最终得分公式应该是**: `final_score = (Σ matched_s_c) / s_max * 100`
- ❌ **当前实现**: s_max 是中间值，未在输出时做最终归一化

**影响**:
- 🔴 **无法设置统一的 bad case 阈值**（原设计目标）
- 🔴 **不同题目无法横向比较**（满分 18 vs 374）
- 🔴 **Excel 中显示"总分: 85"误导性强**（应该是"归一化分母: 85, 满分: 100"）

**修正方案**:
1. **方案 A**: 修改 s09，让 s_max 固定为 100
   ```python
   total_raw = sum(...)
   for c in criteria:
       c['normalized_score'] = (c['score'] / total_raw) * 100
   s_max = 100  # 所有题目统一
   ```

2. **方案 B**: 保持 s_max 为中间值，在 Phase 4 步骤 12 判分时做最终归一化
   ```python
   # s12_judge.py
   final_score = (sum(matched_scores) / rubric['s_max']) * 100
   ```

**推荐**: 方案 B，因为 s_max 作为元数据有价值，判分时归一化更灵活。

## 🟡 重要偏差（影响质量但不阻碍）

### 3. **步骤 11 诊断无处置动作**

**设计要求** (docs §11, 行 209-216):
```
诊断出问题后的处置（诊断没有处置就只是报告）：
- Subjective / Ungrounded / Non-Atomic → 重写该条准则或删
- Redundant Criteria → 合并同簇准则
- Missing Criteria → 退回第 3 步补水平展开
- Misaligned → 退回第 2 步
- Hackable → 降权或改为闸门
- Low Signal → 退回第 7 步补增量准则
```

**实际实现** (`stages/s11_diagnose.py`, 行 16):
```python
# 只把诊断结果附到 criteria[].diagnostics
# **不删除** —— 删不删是 Phase 3 人工复核的事
```

**偏差**:
- ⚠️ 只做诊断，不做处置
- ⚠️ 依赖人工复核，未实现自动化闭环

**影响**:
- 🟡 RIFT 诊断的价值打折扣（只报告不修复）
- 🟡 需要人工介入才能生成合格 rubric

**修正优先级**: 🟡 中等（Phase 3 的定位就是"诊断"，Phase 4 可以补处置逻辑）
