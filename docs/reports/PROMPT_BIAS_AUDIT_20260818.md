# Rubric 生成准确性与 Prompt 偏差审查（2026-08-18）

## 结论

对 outputs/rubrics_advisor_lean.jsonl 采用固定种子 20260818 分层抽检 30 题，覆盖全部 6 道 gated_answer，并覆盖 analytic/multi_part 与 veto 组合。

| 指标 | 结果 |
|---|---:|
| 严格准确（可直接交付） | 3/30 = 10.0% |
| 小修后可用 | 12/30 = 40.0% |
| 存在重大误判风险 | 18/30 = 60.0% |

Wilson 95% 区间：严格准确率约 3.5%-25.6%，可用率约 24.6%-57.7%。样本用于判断问题方向，不应表述为 233 题全量的精确准确率。

## 核心判断

主要问题不是 schema，而是源 prompt 在不同步骤中同时要求模型推测意图、补隐性约束、输出具体应然事实并凑足准则数量。即使另一处写了“不要编造”，模型仍会优先满足更具体、更强势的指令和示例，从而把主观推断、单份回答细节或模型记忆固化为评分标准。

## 逐行审查与修改

### stages/s02_context.py

原指令要求判断“提问者的真实目的”，并以“多半为了写代码”作为正例；又把题面没写的 audience、format、risk boundary 称为“答案必须满足的条件”。修改后，intent 只归纳题面明确任务，约束只记录题面有文字依据的内容，未指定就明确写未指定，标签不能新增评分要求。

### stages/s03_perspective.py

原流程把上游“隐性约束”提供给视角生成器，放大主观推断。修改后，评价轴必须来自题目明确要求、明确条件或完成任务不可缺少的判断，禁止根据推测身份、用途、偏好和单份参考回答新增评价轴。

### stages/s05_ground.py

原指令允许模型判断“明显该答但没答”的 gaps，并称其为 rubric 应覆盖内容。修改后，gaps 只记录题面明确要求但锚定回答未覆盖的方面。

### stages/s04_rubric.py

原“6-8 条硬预算”和“1-2 条扣分项”会在简单题和证据不足题上硬凑。原 prompt 同时要求每条包含具体应然内容并提供大量具体事实正例，容易压过“不编造”要求；还把列举、描述、比较、分析列为高危动词，对研究与总结任务有主观偏见。

修改后：6-8 条为通常范围，仅保留 8 条上限；简单题可少于 6 条；负项允许为 0；明确证据优先级；外部时效事实缺值时评价来源、口径与核验方法，不猜具体值；动词按题目任务判断，不设黑名单；负项必须描述实际出现的错误，不能把正确行为反写成负项。

### stages/s04c_severity.py

原“出现后整份回答不再有任何价值”过于绝对，容易把局部错误、开放观点差异和身份披露升级为 veto。修改后，principle/veto 仅限直接破坏核心任务或直接执行明确禁止且不可接受的行为，并排除措辞偏好、局部遗漏、观点差异、诚实身份披露和可修正小错。

## 典型抽检问题

- q0195：无项目材料却硬编码“12个月、五阶段、客户ID”等细节。
- q0057：把时效性黄金阻力位和支撑位写成固定答案。
- q0200、q0224：答案准则未给可执行答案，只要求“与推导结果一致”或“给出具体值”。
- q0181、q0218：局部材料过拟合，未覆盖用户完整任务。
- q0221：负项极性反写，正确拒绝色情内容反而扣分。
- q0005：把诚实披露 AI 身份设为一票否决，属于价值偏好而非回答正确性。

## 下一轮验证

本轮先修改源 prompt，不新增程序护栏。重新运行受影响链路后，使用两组数据验证：

1. 固定回归集：本次 30 题，检查已知问题是否消失。
2. 新鲜分层集：另抽 50 题，防止对已有 badcase 过拟合。

放行目标：严格准确率不低于 85%，重大错误率不高于 5%，负项方向错误为 0，缺少可靠依据的具体事实硬编码为 0。统计时保留 PASS/MINOR/MAJOR 三档及原始逐题判定，不用单一平均分掩盖重大错误。

## 关键修正：待评分回答不属于 rubric 生成输入

进一步逐行核对源码后确认，问题比“参考回答导致过拟合”更严重：当前 ref_responses 实际就是后续要被评分的回答，却从入口进入了标准生成链路。

当前泄漏路径：

```text
s00_seed.py:48       ref_response → seed.ref_responses
s01_filter.py:71-75  ref_response → query 过滤 prompt
s05_ground.py:116-132  ref_response → anchor / answer / gaps
s04_rubric.py:202-231  anchor / answer / gaps → rubric 生成
s10_pool.py          ref_response → 待评分池/对抗样本参照
s12_judge.py         回答 → rubric 判分
```

正确边界应是：

```text
rubric 生成链：题目 + 题目明确给出的 system/user 约束
                      ↓
                 rubric 完成并冻结
                      ↓
待评分链：candidate/ref response + 已冻结 rubric → judge
```

ref_responses 可以保留在数据集中用于后续 Phase 4 的待评分对象，但不能被 s01、s02、s03、s04、s05 的 rubric 生成链读取。尤其不能再把候选回答抽成 grounding anchor 或 canonical answer。

### 这解释了哪些抽检问题

- q0057：把标准回答中的黄金阻力位、支撑位和机构名称变成硬评分点。
- q0038：把标准回答中的年龄分段、测评工具和“四步法”变成必答项。
- q0195：把参考回答或模型补写的项目细节变成“12个月五阶段”等要求。
- q0101：把标准回答采用的三种建议形式扩展成额外门槛。
- q0190：把单条参考翻译结果变成唯一字符串，误杀同义正确译法。

### 修复优先级

1. s00_seed 将题目输入与候选回答分离保存；保留候选回答用于 Phase 4，但不再让结构线读取。
2. s01_filter 只接收题目和题目约束，不再读取 ref_responses。
3. s02_context、s02b_route、s03_perspective、s04_rubric 只沿用题目链路字段。
4. s05_ground 不再位于 rubric 生成链路；它可以改成 judge 前的候选回答分析工具，或从主线移除。
5. answer_canonical 只能来自题目明确给出的答案或独立、程序化、与 candidate response 无关的求解器，不能从待评分回答抽取。
6. s10_pool 生成的回答必须在 rubric 冻结后产生；它可以读取题目，但不能反向影响 rubric。

本修复不是新增护栏，而是恢复数据流的评测隔离边界。没有完成隔离前，任何 rubric 准确率都不能视为独立评估结果。
