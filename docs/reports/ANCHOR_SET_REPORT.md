# 锚点集（Anchor Set）建设报告

**建设日期**: 2026-08-12  
**对应设计文档**: `docs/design/rubric_pipeline_feishu_v2.md`「前置：锚点集（人在环）」

---

## 为什么需要锚点集

设计文档把它列为「流程之外但必须先有的东西」，理由有两条：

> Qworld 的 Coverage / Uniqueness 都是**相对专家准则集**算的，我们没有专家集，
> 必须自建一个小规模人工审定的 rubric 集当参照，**否则第 11 步的指标没有分母**

> 它同时是**独立于生成模型的质量参照点**。生成、诊断、回灌若共享同一信号源，
> 准则会在自举中缓慢漂移而无人发现

这个环节此前一直空缺。直接后果是：s05 的 drift 判定、s11 的 RIFT 诊断都**没有
参照可校准** —— 判出 30.8% 还是 77.4%，无从判断哪个更接近实际。

---

## 一个必须先说明的自指涉问题

s05 用的判定模型是 `glm-ac`，而 s04 的准则**也是 glm-ac 生成的**。
等于让模型检查自己的作业，存在自偏好倾向。

设计文档只对判分器（步骤 12）强制要求异质（「判分器 ≠ 生成器」），
步骤 5 无此约束，所以不算违规。但既然要建参照点，就必须换一个独立信号源，
否则「参照」本身也在同一个偏差里。

## 方案设计

### 判定模型：异质闭源模型

| 项 | 值 |
|----|-----|
| 模型 | `gpt-5.6-sol` |
| family | `openai`（与 glm / deepseek 异质）|
| 角色 | `grounder` / `diagnoser` / `judge` |
| 说明 | 临时 key，2026-08-13 过期 |

### 为什么用 5 票多数投票（LLMaJ-MV）

上线前实测发现该端点**判定不稳定**：同一条准则连判 4 次得到
`clean / clean / drift / clean`，`temperature` 已设 0 仍有服务端波动。

单次跑的结论不可用。RIFT 论文对 Reliability 三项同样采用 N=5 多数票，
正是为压住这种方差。故本方案取 5 票。

### 同期排除的候选

| 模型 | 延迟 | 结果 |
|------|------|------|
| `gpt-5.6-luna` | 2.8s（最快）| ❌ 对 s05 的 prompt **稳定返回 502** |
| `gpt-5.6-sol` | 6.7s | ✅ 采用 |
| `gpt-5.6-terra` | 9.3s | 未测（延迟最高）|

luna 的 502 与 prompt 长度无关 —— 17,500 字的其他内容能通，s05 的 2,582 字不通，
推测是网关侧对特定内容的拦截。换 luna 解决不了问题。

### 抽样设计：两类各半，而非按真实占比

s05 全量的真实分布是 drift 30.8% / clean 69.2%。但抽样**刻意取各 250 条**，
原因是要同时测 glm-ac 的两个指标：

- **精确率**：glm 判 drift 的里面有多少真脱靶 → 需要足够的 drift 样本
- **召回率**：真脱靶的里面 glm 抓到多少 → 需要足够的 clean 样本（漏检藏在这里）

按 30.8% 抽的话 clean 类样本会不足，召回率测不准。

代价是「抽样内原始一致率」不能直接外推到全量，所以报告里另算一个
**按真实占比加权的一致率**，那个才代表全量 13,788 条上的预期表现。

每类内部再按 `rubric_form` 比例分层：

| glm 判定 | analytic | gated_answer | multi_part | 小计 |
|----------|----------|--------------|------------|------|
| drift | 174 | 14 | 62 | 250 |
| clean | 152 | 12 | 86 | 250 |
| **合计** | **326** | **26** | **148** | **500** |

固定随机种子 `20260812`，抽样可复现。

### 规模与成本

```
500 条 × 5 票 = 2,500 次调用
```

## 试跑发现（20 条 × 3 票）

全量跑之前先小批验证链路，结果已暴露一个重要问题。

### glm-ac 在小样本上一致率仅 70%

| | anchor:drift | anchor:clean |
|---|---|---|
| **glm:drift** | 7 | 3（误杀）|
| **glm:clean** | 3（漏检）| 7 |

误杀与漏检对称，无系统性偏向。

### 关键发现：glm-ac 漏检「领域事实性幻觉」

这是用异质闭源模型做锚点最直接的收益 —— 抓到了 glm-ac 完全看不见的一类问题：

**案例 1（量子化学，3/3 票判 drift）**

- 题目：用 DFT 优化结构后跑 TDDFT，精度不够，准备加 CCSD(T)
- 准则：「明确要求基于 CCSD 参考态计算 T1 诊断，并据此判断 CCSD(T) 对**目标激发态**的适用性」
- 锚点理由：**幻觉** —— 基态 CCSD 的 T1 诊断不能据此判断 CCSD(T) 对激发态的适用性

T1 诊断是基态多参考特征的指标，用它推断激发态适用性是实质性错误。
glm-ac 判 clean。

**案例 2（高分子表征，3/3 票判 drift）**

- 题目：漆酚与全氟辛基乙基丙烯酸酯高温共聚，如何判断发生了聚合，NMR 可以吗
- 准则：「指出高温下漆酚氧化交联成膜导致不溶不熔，使液相 NMR 无法制样，需改用固态 NMR」
- 锚点理由：**幻觉** —— 未给出温度、气氛等条件，不能断定必然交联成膜

准则把一个条件依赖的结论当成必然，glm-ac 判 clean。

**案例 3（气敏材料，2/3 票判 drift）**

- 准则：「说明其加速了表面吸附氧反应时电子的得失与输运，**提升响应速度**」
- 锚点理由：**超范畴** —— 题目未给出响应速度数据，准则却要求断言响应速度提升

### 为什么这类漏检特别重要

s05 的 prompt 里列了三类 drift：①超出题目范畴 ②笼统空泛 ③幻觉。
glm-ac 对 ①② 的识别尚可，但对 **③ 幻觉几乎无能** —— 因为判断"这个领域结论对不对"
需要该领域的实际知识，而这些准则正是 glm-ac 自己写的，它认为自己写的是对的。

这直接印证了设计文档那句「生成、诊断、回灌若共享同一信号源，准则会在自举中
缓慢漂移而无人发现」。

### 一个三方对照：prompt 修对了，但模型能力上限仍在

`q0117-c35`（T1 诊断那条）在三次判定中的表现：

| 判定源 | 结论 | 理由 |
|--------|------|------|
| 旧 s05（错误 prompt）| drift | 「参考回答未涉及，要求过高」← **理由是错的** |
| 新 s05（修正 prompt）| clean | — |
| 锚点 gpt-sol（5 票）| **drift** | 「幻觉：基态 CCSD 的 T1 诊断不能判断激发态适用性」|

修正 prompt 确实修对了「不该拿参考回答当标准」这个逻辑错误 —— 旧判定虽然结论
碰巧是 drift，但理由完全不成立。

然而修正后 glm-ac 转判 clean，**仍然没看出这是领域幻觉**。说明：
- prompt 层面的问题（判定标准写错）已解决
- 模型层面的能力上限依旧存在 —— 识别领域幻觉需要该领域知识，
  而 glm-ac 正是这些准则的作者

这两类问题必须分开看：前者靠改 prompt，后者只能靠换异质模型。

## 附带发现：s11 也是同源诊断

排查时发现 s11 的 RIFT 诊断同样存在自指涉：

```
诊断器: glm-ac (family=glm)
生成器: glm-ac (family=glm)   ← 同一个
```

这**违反**了设计文档对步骤 11 的明确要求：

> 步骤 11(RIFT 诊断): `diagnoser` 需**异质组合**
> （Gemini 系强于 Ungrounded/Subjective，GPT 系强于 Missing/Low Signal）

配置里 `deepseek` 也带 `diagnoser` 角色，但 `stage.pick` 取的是列表里第一个匹配的，
即 glm-ac。修的话需要显式指定 `RP_M_DIAGNOSER=deepseek`，或改成多模型投票。

### 但换异质开源模型并不能解决 —— 这是能力问题，不是同源问题

顺手做了个对照实验：把 s11 的 ungrounded 诊断换成 `deepseek`（family=deepseek，
与 glm 异质），在那三条准则上跑：

| 准则 | 锚点 gpt-sol | glm-ac | deepseek |
|------|-------------|--------|----------|
| q0117-c35 | drift（幻觉）| defective ✓ | defective ✓ |
| q0186-c35 | drift（幻觉）| clean ✗ | clean ✗ |
| q0291-c10 | drift（超范畴）| clean ✗ | clean ✗ |

**deepseek 与 glm-ac 判定完全一致（3/3 相同）**，都只抓到 1 条。

这推翻了「同源导致漏检」的初步推断。真正的原因是：

- 识别「基态 T1 诊断不能判断激发态适用性」这类错误，需要**量子化学的实际知识**
- 两个开源模型都不具备足够的领域深度，异质与否不影响结果
- 只有 gpt-5.6-sol 这类闭源高端模型能稳定抓到（3/3 票一致）

**推论**：换 `RP_M_DIAGNOSER=deepseek` 满足了设计文档的异质要求（形式上合规），
但对幻觉类问题没有实质改善。要真正提升，得用闭源高端模型或多模型投票。

注意 deepseek 给 q0117-c35 的理由是「超出用户问题范畴」，而锚点的理由是
「幻觉：T1 诊断不能判断激发态」—— 结论相同但归因不同，deepseek 是"蒙对"的。

### 另一个数据血缘问题

`s11_diagnosed.jsonl`（11:55 生成）里内嵌的 `grounding` 字段是**修正前**的旧 s05
结果，而 `s05_grounded.jsonl`（12:12）是修正后重跑的。两个文件的同名字段不一致。

不影响 RIFT 诊断本身（诊断只读准则文本，不读 grounding），但读数据时要注意：
**以 `s05_grounded.jsonl` 为准**。

### 另一个数据血缘问题

`s11_diagnosed.jsonl`（11:55 生成）里内嵌的 `grounding` 字段是**修正前**的旧 s05

不影响 RIFT 诊断本身（诊断只读准则文本，不读 grounding），但读数据时要注意：

## 全量结果

⏳ 2,500 次调用进行中，完成后补录。

查看报告：
```bash
python3 scripts/anchor_report.py
```

报告含：投票可靠性、混淆矩阵、精确率/召回率/F1、加权一致率、
Cohen's kappa、按 rubric_form 分层、漏检样例。

### 结论如何影响后续动作

按 kappa 分档决定处置策略：

| kappa | 判断 | 动作 |
|-------|------|------|
| ≥ 0.6 | 良好 | glm-ac 全量判定可直接沿用 |
| 0.4–0.6 | 中等 | 只处置 glm 与锚点**都**判 drift 的交集，对高发误差类型改 prompt 重跑 |
| < 0.4 | 偏低 | glm-ac 判定不可用于处置，需改 prompt 重跑或全量改用锚点模型 |

## 产出文件

| 文件 | 内容 |
|------|------|
| `stages/s05b_anchor.py` | 抽样 + 5 票投票 |
| `data/s05b_anchor.jsonl` | 500 条，含 5 票明细、多数票结论、glm 原判定 |
| `scripts/anchor_report.py` | 校准报告 |

`s05b_anchor.jsonl` 每条记录的字段：

```
rid, criterion_id, rubric_form, question, positive, negative
glm_verdict        glm-ac 的 s05 判定
glm_reason         glm-ac 的理由
anchor_votes       5 票明细，如 ["drift","drift","clean","drift","drift"]
anchor_n_drift     判 drift 的票数
anchor_verdict     多数票结论
anchor_unanimous   是否全票一致
anchor_reasons     判 drift 的理由（最多 3 条）
```
