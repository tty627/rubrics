## 关键改进点

### 1. 信息优先级重构
**原版问题**: 端点状态（prio=6）排在中间，但这是最关键的健康指标
**新版方案**: 端点健康度提到状态栏第一条，一眼看出异常

### 2. 添加速率趋势
**原版**: 只显示瞬时速率（次/分钟）
**新版**: 添加趋势箭头
- `↑` 加速中（后段速率 > 前段 × 1.15）
- `→` 平稳
- `↓` 减速中（后段速率 < 前段 × 0.85）

**价值**: 快速判断流水线是否卡住或加速

### 3. 添加成本估算
**原版**: 只统计Token数量
**新版**: 根据模型价格计算实际成本
- DeepSeek: $0.27/M 输入 + $1.10/M 输出
- Qwen: $0.30/M 输入 + $0.60/M 输出
- GLM: $0.50/M 输入 + $0.50/M 输出

**价值**: 实时了解花费，预算控制

### 4. 默认折叠非活跃步骤
**原版**: 显示所有14个步骤（即使未开始）
**新版**: 只显示活跃步骤，折叠显示统计
- `✓ 已完成 6 步`
- `○ 未开始 5 步  (展开用 --all)`

**价值**: 减少视觉噪音，聚焦当前任务

### 5. 删减冗余信息

| 删减内容 | 原因 | 替代方案 |
|---------|------|---------|
| 进程详情（pid/线程/socket） | 调试用，日常监控不需要 | `ps aux \| grep stages` |
| 在飞请求的完整prompt/output | 占用大量空间，通常只需统计 | 保留计数，内容需要时用原版 |
| 最近完成的详细内容 | 同上 | 改为成功率+平均耗时 |
| 产出文件列表 | 静态信息 | `ls -lh data/` |

### 6. 合并重复统计
**原版**: Token统计分两块
- "Token 用量"（流水线侧）
- "端点侧 token"（服务端统计）

**新版**: 合并为一个资源区块，避免混淆

### 速率趋势算法
```python
class ScanV2(Scan):
    def __init__(self):
        super().__init__()
        self.rate_history = {}  # stage → deque([时间戳, 速率])
    
    def trend(self, stage):
        hist = self.rate_history.get(stage, [])
        if len(hist) < 3:
            return 'flat'
        # 比较前半段和后半段平均值
        mid = len(rates) // 2
        avg1 = sum(rates[:mid]) / mid
        avg2 = sum(rates[mid:]) / (len(rates) - mid)
        if avg2 > avg1 * 1.15: return 'up'
        elif avg2 < avg1 * 0.85: return 'down'
        return 'flat'
```
