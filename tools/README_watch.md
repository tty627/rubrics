# 监控面板使用说明

## 两个版本对比

### watch.py（原版，详尽模式）
- 1000+ 行代码，8个信息区块
- 显示进程详情（pid、socket连接、环境变量）
- 显示在飞请求的完整prompt/output
- 显示最近完成调用的详细内容
- 显示产出文件列表
- 适合：深度调试、排查问题

### watch_v2.py（新版，概览模式）
- 300行代码，3层结构
- 只显示关键信息：状态、进度、成本
- 默认折叠未开始/已完成步骤
- 添加速率趋势（↑加速 ↓减速）
- 添加成本估算
- 适合：日常监控、快速了解状态

## watch_v2.py 用法

### 基本用法
```bash
# 全屏实时刷新（推荐）
python3 tools/watch_v2.py

# 快照模式（打印一次退出）
python3 tools/watch_v2.py --once

# 展开所有步骤（包括未开始/已完成）
python3 tools/watch_v2.py --all

# 自定义刷新间隔（默认2秒）
python3 tools/watch_v2.py -n 5

# 不探测端点（纯本地）
python3 tools/watch_v2.py --no-probe
```

## 三层信息结构

### 1. 状态栏（1行）
- **端点健康度** - 一眼看出是否有端点离线
- **当前任务** - 正在运行的脚本
- **关键指标** - 如有异常会高亮显示

### 2. 进度表
- **活跃步骤** - 正在运行或最近有活动的步骤
  - 进度条：14字符，满格表示完成
  - 速率：次/分钟
  - 趋势：↑加速 →平稳 ↓减速
  - ETA：预计剩余时间
- **折叠信息** - 已完成和未开始步骤默认折叠（用`--all`展开）

### 3. 资源统计
- **Token用量** - 输入/输出/思维链占比
- **成本估算** - 基于不同模型价格计算
- **端点负载** - 每个端点的运行/排队请求数和吞吐量
- **调用统计** - 最近成功率、平均耗时

## 图标说明

### 步骤状态
- `▶` 正在运行（绿色）
- `⏸` 已暂停/停滞（黄色）
- `✓` 已完成（绿色）
- `○` 未开始（灰色）

### 端点状态
- `✓` 正常（绿色）
- `✗` 离线/异常（红色）

### 速率趋势
- `↑` 加速中（绿色）
- `→` 平稳
- `↓` 减速中（红色）

## 技术细节

### 速率趋势判断
- 记录最近5个采样点
- 比较前半段和后半段平均值
- 加速：后段 > 前段 × 1.15
- 减速：后段 < 前段 × 0.85

### 成本估算
基于以下价格表（美元/M tokens）：
- DeepSeek: $0.27 输入 / $1.10 输出
- Qwen: $0.30 输入 / $0.60 输出
- GLM: $0.50 输入 / $0.50 输出
- GPT: $2.50 输入 / $10.00 输出

### 数据来源
- 进度/Token：`cache/<stage>/*.json`
- 调用统计：`cache/_events.jsonl`
- 端点负载：`/metrics` 端点
- 进程信息：`/proc/<pid>/`

## 常见问题

### Q: 为什么成功率不是100%？
A: LLM调用可能因为JSON格式错误、超时等原因失败，流水线会自动重试。成功率 >90% 是正常的。

### Q: 为什么ETA是 ? ？
A: 某些步骤无法预估总调用数（如未在PIPE中登记），此时ETA无法计算。

### Q: 思维链占比很高正常吗？
A: DeepSeek-V3等模型的思维链token可能占输出token的60-90%，这是正常的。

### Q: 速率趋势一直是 → ？
A: 需要至少3个采样点且速率变化>15%才会显示趋势，初期数据不足时显示平稳。
